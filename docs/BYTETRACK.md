# ByteTrack 동작 원리와 구현 (요구 사항 2)

이 프로젝트는 Ultralytics에 들어 있는 추적기를 호출하지 않고, ByteTrack을 `tracker/` 폴더에 직접 구현했습니다.
YOLO11n은 **프레임마다 박스와 신뢰도만** 내고, 박스를 이전 프레임의 객체와 연결해 ID를 유지하는 일은 모두 아래 코드가 합니다.

| 파일 | 역할 |
|---|---|
| `tracker/kalman.py` | 등속 운동 칼만 필터: 다음 프레임 위치 예측과 보정 |
| `tracker/matching.py` | IoU·외형 비용 계산, 헝가리안 할당 |
| `tracker/byte_tracker.py` | 트랙 상태 관리와 ByteTrack 연결 절차, 개선 기능 |
| `tracker/appearance.py` | 개선판에서 쓰는 색 히스토그램 외형 특징 |
| `tracker/motion.py` | 객체별 이동 방향·거리·속도·궤적 계산 |

## 1. 핵심 아이디어: 낮은 신뢰도 검출도 버리지 않는다

일반적인 추적기는 신뢰도가 낮은 검출(예: 0.5 미만)을 버립니다. 그런데 사람이 다른 사람이나 기둥에 가려지면
검출기의 신뢰도가 먼저 떨어집니다. 이 검출을 버리면 가려지는 순간 트랙이 끊기고, 다시 보일 때 새 ID가 붙습니다.

ByteTrack은 검출을 **높은 신뢰도 / 낮은 신뢰도**로 나눠 두 번 연결합니다.
낮은 신뢰도 검출은 **이미 추적 중인 객체와 위치가 맞을 때만** 사용하므로, 배경 오검출이 새 트랙을 만들지 않으면서도
가려지는 사람을 계속 따라갈 수 있습니다.

## 2. 한 프레임의 처리 순서 (`ByteTracker.update`)

```
검출 (boxes, scores)
  ├─ score ≥ high_thresh(0.5)          → 높은 신뢰도 D_high
  └─ low_thresh(0.1) < score < 0.5     → 낮은 신뢰도 D_low

1) 예측   모든 트랙(추적 중 + Lost)의 위치를 칼만 필터로 한 프레임 앞으로 예측
2) 1차    D_high ↔ (추적 중 + Lost) 트랙
          비용 = 1 − IoU(예측 박스, 검출 박스)×score, 헝가리안 할당, 비용 ≤ match_thresh(0.8)
3) 2차    1차에서 남은 '추적 중' 트랙 ↔ D_low, IoU 비용 ≤ 0.5
4) Lost   2차에서도 남은 트랙은 Lost로 표시 (삭제하지 않고 기다림)
5) 확정   직전 프레임에 생긴 미확정 트랙 ↔ 남은 D_high (두 프레임 연속 검출되어야 확정)
6) 생성   남은 D_high 중 score ≥ new_track_thresh(0.6) → 새 ID
7) 삭제   track_buffer(30프레임) 넘게 다시 연결되지 않은 Lost 트랙 → Removed
```

### 칼만 필터 (이동 예측)
상태 `(cx, cy, a, h, vcx, vcy, va, vh)`에서 다음 위치를 `위치 + 속도`로 예측하고, 연결된 검출로 보정합니다.
예측 덕분에 빠르게 움직이는 사람도 이전 박스가 아닌 **예측 박스**와 비교되어 IoU가 유지됩니다.
잡음 크기는 박스 높이에 비례하게 두어, 멀리 있는 작은 사람과 가까운 큰 사람을 같은 비율로 다룹니다.

### 헝가리안 할당 (연관성 판단)
트랙 N개와 검출 M개의 비용 행렬에서 **비용 합이 최소인 1:1 짝**을 구합니다(`scipy.optimize.linear_sum_assignment`).
비용이 임계값을 넘는 짝은 버리므로, 겹치지 않는 박스끼리 억지로 연결되지 않습니다.

### 트랙 상태 관리
| 상태 | 의미 | 화면 표시 |
|---|---|---|
| New | 처음 검출, 아직 확정 전 | 표시 안 함 |
| Tracked | 이번 프레임에 연결됨 | 실선 박스, `추적 중` (다시 찾은 직후 1초는 `재등장`/`재진입`) |
| Lost | 연결 실패, 다시 나타나기를 기다림 | 점선 회색 박스, `가림` 또는 `화면 이탈` |
| Removed | `track_buffer`를 넘김 | 사라짐 (개선판은 외형을 갤러리에 보관) |

`가림`과 `화면 이탈`은 Lost가 되는 순간 박스가 화면 가장자리에 닿아 있고 바깥쪽으로 움직이고 있었는지로 구분합니다.

## 3. 개선판 (요구 사항 3·4)

기본판의 한계와 각각의 개선입니다. `TrackerConfig`의 항목으로 하나씩 켜고 끌 수 있어 효과를 따로 측정할 수 있습니다.

| 한계 | 개선 (설정 항목) | 바뀐 구성 요소 |
|---|---|---|
| 두 사람이 교차하면 IoU만으로는 누가 누구인지 헷갈림 | 1차 연결 비용에 색 히스토그램 외형 거리를 섞음: `0.7×IoU비용 + 0.3×외형거리`, 외형 거리 0.4 초과 시 연결 금지 (`appearance`) | 특징 추출, 연관성 판단 |
| 오래 가려지면 예측 박스가 실제 위치와 어긋나 IoU가 0이 되어 재연결 실패 | 남은 검출 ↔ Lost 트랙을 외형 + 이동 반경(가려진 시간에 비례) + 크기 비율로 3차 연결 (`recover_lost`) | 연관성 판단, 상태 관리 |
| 화면 밖으로 나갔다 들어오면 무조건 새 ID | 삭제된 트랙의 외형을 150프레임 보관, 비슷한 사람이 들어오면 이전 ID 복원 (`reid_buffer`) | 상태 관리 |
| 화면 밖으로 나간 트랙의 예측 위치가 계속 바깥으로 흘러감 | 화면 이탈로 판정된 트랙은 위치를 고정 (`freeze_out_of_frame`) | 이동 예측 |
| (시도 후 제외) 가려진 동안 예측이 멀리 흘러갈 수 있음 | 가려진 동안 속도를 프레임마다 15% 감쇠 (`damp_lost_velocity`). 합성 장면에서 단독 적용 시 HOTA 84.0 → 71.2, IDSW 1 → 3으로 **나빠져** 기본 개선판에서 뺐습니다. 기둥 뒤를 지나는 사람은 계속 같은 속도로 걷기 때문에 등속 예측이 맞습니다. | 이동 예측 |
| 겹친 박스의 색에 다른 사람이 섞여 외형이 오염됨 | 다른 검출과 IoU 0.3 이상 겹친 박스로는 외형을 갱신하지 않음 | 특징 추출 |

외형 특징은 박스 안쪽 80%를 위·아래(상의·하의)로 나눠 각각 HSV(Hue 16 × Saturation 4) 히스토그램을 구한 128차원 벡터입니다.
학습이 필요 없고 CPU에서 사람당 약 0.2 ms(추적 단계 전체 1~2 ms)라 실시간 처리 속도에 영향이 거의 없습니다.
트랙의 외형은 지수 이동 평균(0.9)으로 갱신해 순간적인 조명 변화에 덜 민감하게 했습니다.

## 4. 파라미터 (요구 사항 6)

| 항목 | 기본값 | 의미 | 탐색 범위 (`tune_params.py`) |
|---|---|---|---|
| `high_thresh` | 0.5 | 1차 연결에 쓰는 검출 신뢰도 (검출 임계값) | 0.4, 0.5, 0.6 |
| `new_track_thresh` | high + 0.1 | 새 ID를 만들 최소 신뢰도 | high에 연동 |
| `match_thresh` | 0.8 | 1차 연결 비용 상한 (연관성 임계값) | 0.7, 0.8, 0.9 |
| `track_buffer` | 30 | Lost 트랙 유지 프레임 (추적 유지 시간, 30fps 기준) | 30, 60, 90 |

검증(val) 구간에서 HOTA가 가장 높은 조합을 `configs/tuned.json`으로 저장하고, 테스트(test) 구간에서 최종 성능을 보고합니다.
