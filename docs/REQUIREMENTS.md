# 요구 사항별 구현 대응표

과제 「3.5 지능형 객체 추적 시스템」의 제한 요소 및 요구 사항 10개를 각각 어떤 파일과 명령으로 충족하는지 정리했습니다.
사용 데이터셋은 **COCO**(사람·고양이·개·새 검출), **MOT17/MOT20**(보행자 추적 평가), **CrowdHuman**(붐비는 장면 사람 검출),
**WIDER FACE**(얼굴 모자이크) 4가지입니다.

> **수치에 대해**: 아래 "검증 결과"는 이 저장소에서 실제로 실행해 확인한 값입니다. 공식 MOT17/MOT20 데이터는
> 개발 환경에서 내려받을 수 없어, MOT 수치 대신 **정답을 아는 합성 장면**(`tests/synthetic.py`)과 `sample.mp4`로 검증했습니다.
> 보고서용 MOT 성능은 아래 "전체 실행 순서"를 실제 데이터로 실행해 채워야 합니다.

## 1. 데이터 준비: 학습·검증·테스트 구분과 전처리

| 데이터셋 | 명령 | train / val / test |
|---|---|---|
| COCO | `prepare_dataset.py coco` | train2017에서 해시로 90% / 10% 분리, val2017 = test. person·dog·cat·bird 4클래스만 YOLO 라벨로 변환 |
| CrowdHuman | `prepare_dataset.py crowd` | 공식 train 90% / 10%, 공식 val = test. `fbox` 사용, `ignore` 박스 제외 |
| WIDER FACE | `prepare_dataset.py face` | 공식 train 90% / 10%, 공식 val = test. invalid 박스 제외 |
| MOT17·MOT20 | `prepare_dataset.py mot` | 시퀀스마다 앞 50% / 다음 25% / 마지막 25% 프레임 |

* 분할은 파일명 해시로 정해져 다시 실행해도 같고, `splits.json`에 분할 기준과 이미지·박스 수가 기록됩니다.
* MOT는 **두 가지 형식**으로 전처리합니다. ① 검출 학습용 YOLO 라벨(5프레임 간격, 30% 이상 보이는 보행자)
  ② 추적 평가용 MOT 시퀀스(`tracking/<split>/<seq>`): **객체 ID·위치·가시 비율을 그대로 보존**하고 프레임 번호만 1부터 다시 매김.
* MOT17은 같은 영상이 DPM/FRCNN/SDP로 3번 들어 있어 `--detector FRCNN` 하나만 사용합니다 (중복 평가 방지).

**검증**: `sample.mp4`를 MOT 형식으로 바꾼 400프레임 시퀀스에서 train 200 / val 100 / test 100프레임으로 나뉘고,
ID가 보존된 `gt.txt`와 `seqinfo.ini`가 생성되는 것을 확인했습니다.

## 2. 기존 추적 알고리즘으로 고유 ID 부여, 원리 설명과 처리 과정 구현

* ByteTrack을 **직접 구현**했습니다 (`tracker/`). Ultralytics의 `model.track()`은 더 이상 사용하지 않고, YOLO는 검출(`predict`)만 합니다.
  * `tracker/kalman.py`: 등속 칼만 필터 (예측·보정)
  * `tracker/matching.py`: IoU 비용, 신뢰도 반영, 헝가리안 할당
  * `tracker/byte_tracker.py`: 높은/낮은 신뢰도 2단계 연결, 트랙 생성·확정·Lost·삭제
* 동작 원리 설명: [`docs/BYTETRACK.md`](BYTETRACK.md)

**검증**: `tests/test_core.py`의 칼만 예측, 클래스 분리, 상태 판정 테스트 통과. `sample.mp4` 150프레임에서 사람마다 ID가 붙어 유지됩니다.

## 3. 추적 모델 개선과 전후 비교

개선판(`improved`)은 기본판에 다음을 추가했습니다. 자세한 내용은 `docs/BYTETRACK.md` 3절에 있습니다.

| 개선 | 바뀐 구성 요소 |
|---|---|
| 색 히스토그램 외형 거리를 1차 연결 비용에 결합 (`appearance`) | 특징 추출, 연관성 판단 |
| 오래 가려진 트랙을 외형 + 이동 반경으로 재연결 (`recover_lost`) | 연관성 판단, 상태 관리 |
| 화면 밖으로 나갔던 사람에게 이전 ID 복원 (`reid_buffer`) | 상태 관리 |
| 화면 이탈 트랙의 예측 위치 고정 (`freeze_out_of_frame`) | 이동 예측 |

각 항목은 따로 켜고 끌 수 있어 `run_mot.py --trackers baseline baseline+appearance baseline+recover_lost ...`로
항목별 효과(ablation)를 실제 MOT 데이터에서 측정할 수 있습니다.

**검증 (합성 장면, 120프레임, 4명: 교차·기둥 가림·화면 이탈 후 재진입)**

| 설정 | HOTA | AssA | IDF1 | MOTA | IDSW | 생성된 ID 수 (정답 4) |
|---|---:|---:|---:|---:|---:|---:|
| 기본판 (baseline) | 84.00 | 81.30 | 90.30 | 92.17 | 1 | 5 |
| 기본판 + 외형 연결 (`appearance`) | 84.00 | 81.30 | 90.30 | 92.17 | 1 | 5 |
| 기본판 + 가림 후 재연결 (`recover_lost`) | 84.00 | 81.30 | 90.30 | 92.17 | 1 | 5 |
| 기본판 + 재진입 ID 복원 (`reid_buffer`) | 87.23 | 87.50 | 96.17 | 92.63 | 0 | 4 |
| 기본판 + 화면 밖 위치 고정 (`freeze_out_of_frame`) | 84.00 | 81.30 | 90.30 | 92.17 | 1 | 5 |
| 기본판 + 속도 감쇠 (`damp_lost_velocity`, 제외) | 71.15 | 58.69 | 65.55 | 91.24 | 3 | 7 |
| **개선판 (improved)** | **87.23** | **87.50** | **96.17** | **92.63** | **0** | **4** |

* 이 장면에서 기본판의 실패는 화면 밖으로 나갔다 들어온 사람에게 새 ID가 붙는 것 하나였고, 재진입 ID 복원이 이를 해결했습니다.
* 외형 연결과 가림 후 재연결은 이 장면에서는 차이가 없었습니다. 기둥 가림이 짧아 기본판도 30프레임 버퍼로 다시 이어 붙였기 때문입니다. **효과는 MOT 데이터에서 측정해야 합니다.**
* 가려진 동안 속도를 줄이는 방법은 오히려 나빠져(HOTA −12.9) 개선판에서 제외했습니다.
* 같은 결과를 seed 0·1·2 세 장면에서 반복 확인했습니다 (개선판 IDSW 0, ID 수 4).

## 4. 겹침·가림·화면 이탈 시 ID 변경 최소화, 재등장 시 상태 관리

* 트랙 상태를 `추적 중` / `가림` / `화면 이탈` / `재등장` / `재진입`으로 구분합니다 (`tracker/byte_tracker.py`).
  * Lost가 되는 순간 박스가 화면 가장자리에 있고 바깥쪽으로 움직이고 있었으면 `화면 이탈`, 아니면 `가림`
  * 가림 후 다시 연결되면 `재등장`, 화면 밖에서 돌아와 이전 ID를 받으면 `재진입` (약 1초간 표시)
* GUI에 가림·이탈 트랙을 점선 회색 박스로 보여 주고, 객체 목록에 상태를 표시합니다. 결과 CSV에도 상태가 저장됩니다.
* `analyze_failures.py`가 ID 변경 사례를 교차·가림·화면 경계로 분류해 개선 효과를 상황별로 확인합니다.

**검증**: 합성 장면에서 개선판 IDSW 0, 재진입 시 같은 ID 유지 (위 표). `sample.mp4`에서 오른쪽 끝으로 나가는 사람이 `화면 이탈`로 표시됩니다.

## 5. 객체별 위치 변화 기록, 이동 방향·거리·궤적 계산과 시각화

* `tracker/motion.py`: 박스 중심 기준으로 8방향 화살표, 누적 이동 거리(px), 이동 속도(px/s, 지수 평균), 최근 45프레임 궤적
* GUI: 궤적 선, 객체 목록의 방향·거리·속도 열. 결과 CSV에 프레임별 위치·방향·거리·속도 저장

**검증**: `tests/test_core.py::MotionTest` (방향 →, 거리 40px, 궤적 5점) 통과.

## 6. Fine-tuning과 주요 파라미터 최적화

* **Fine-tuning** (`train_models.py`): COCO(4클래스) / CrowdHuman / MOT / WIDER FACE. AdamW, lr 0.0005, 앞 10개 레이어 고정이 기본이고,
  학습 후 val·test 분할로 mAP를 측정합니다. `--install`을 주면 `models/`에 설치하면서 학습 설정과 성능을 `.json`으로 함께 저장합니다.
* **파라미터 탐색** (`tune_params.py`): 검출 임계값(`high_thresh`), 연관성 임계값(`match_thresh`), 추적 유지 시간(`track_buffer`)
  격자 탐색 3×3×3 = 27조합. **val 구간**에서 HOTA 최대 조합을 `configs/tuned.json`으로 저장하고, **test 구간**에서 최종 보고합니다.
  검출 결과를 캐시해서 조합마다 추적기만 다시 돌립니다.

**검증**: MOT 형식 시퀀스에서 MOT 1에폭 학습 → val/test mAP 출력과 `best.json` 생성, 8조합 탐색 → `configs/tuned.json` 생성까지 실행했습니다.
(동작 확인용 데이터라 수치는 의미가 없어 기록하지 않았습니다.)

## 7. HOTA·IDF1·MOTA·IDSW로 성능 분석, 가림·교차 실패 사례 분석

* `metrics.py`: TrackEval(MotChallenge2DBox)의 계산 방식을 그대로 옮긴 HOTA(DetA·AssA·LocA), MOTA, IDF1, IDSW, Frag.
  외부 저장소 없이 평가·튜닝·GUI 비교가 동작합니다. 공식 도구 교차 확인용 `evaluate_mot.py`(TrackEval)도 유지했습니다.
* `analyze_failures.py`: ID 변경(IDSW)과 끊김(Frag)이 일어난 프레임을 찾아 **교차**(다른 사람과 IoU ≥ 0.3), **가림**(visibility < 0.5),
  **화면 경계**, 기타로 분류한 표(`summary.md`), 전체 사례 목록(`events.csv`), 사례 이미지(정답 흰색, 이전 ID 빨강, 새 ID 초록)를 만듭니다.

**검증**: 합성 시퀀스 200프레임에서 `metrics.py`와 공식 TrackEval의 결과가 **모든 지표에서 소수점 셋째 자리까지 같았습니다.**

| 추적기 | 도구 | HOTA | DetA | AssA | MOTA | IDF1 | IDSW | Frag |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| baseline | metrics.py | 83.286 | 86.605 | 80.100 | 91.995 | 88.559 | 1 | 3 |
| baseline | TrackEval | 83.286 | 86.605 | 80.1 | 91.995 | 88.559 | 1 | 3 |
| improved* | metrics.py | 86.892 | 86.698 | 87.087 | 92.266 | 95.977 | 0 | 3 |
| improved* | TrackEval | 86.892 | 86.698 | 87.087 | 92.266 | 95.977 | 0 | 3 |

\* 지표 일치 확인은 속도 감쇠를 빼기 전의 개선판 결과 파일로 했습니다. 같은 결과 파일을 두 도구에 넣어 비교한 것이므로 결론에는 영향이 없습니다.

단위 테스트로 완벽한 추적 = 100점, ID 맞바뀜 = IDSW 2·IDF1 50, 프레임 누락 = FN을 확인합니다.

## 8. 연속 검출·추적, 평균 처리 시간·FPS 측정, 속도 요인 분석

* GUI 입력: 영상 파일 또는 **카메라**(번호 선택). 프레임 순서대로 연속 처리합니다.
* GUI 표시: 현재 FPS, **평균 FPS와 평균 ms**, 단계별(검출·추적·모자이크) 평균 시간
* `benchmark_speed.py`: 입력 크기, 추적기, 얼굴 모자이크, 가중치를 하나씩 바꿔 측정하고, 객체 수와 처리 시간의 상관도 계산합니다.

**검증** (`results/speed.md`, 클라우드 개발 환경 CPU, `sample.mp4` 60프레임, 앞 5프레임 제외):

| 조건 | 검출 ms | 추적 ms | 모자이크 ms | 전체 ms | FPS |
|---|---:|---:|---:|---:|---:|
| 기준 (640, baseline, 모자이크 끔) | 48.7 | 0.76 | 0.0 | 49.4 | 20.2 |
| 입력 크기 320 | 16.2 | 0.60 | 0.0 | 16.8 | 59.5 |
| 입력 크기 480 | 36.6 | 0.76 | 0.0 | 37.3 | 26.8 |
| 입력 크기 960 | 92.4 | 0.84 | 0.0 | 93.3 | 10.7 |
| 추적기 improved | 55.1 | 1.46 | 0.0 | 56.5 | 17.7 |
| 얼굴 모자이크 켬 | 57.8 | 0.80 | 56.0 | 114.7 | 8.7 |

* 처리 시간의 대부분은 **검출**이고, 입력 크기에 거의 비례합니다 (320 → 960에서 약 5.7배).
* 추적 자체는 1 ms 안팎이며, 개선판의 외형 특징 계산은 프레임당 약 0.7 ms를 더합니다.
* 얼굴 모자이크는 검출기를 한 번 더 돌리므로 처리 시간이 약 2배가 됩니다.
* 측정값은 실행 환경마다 다르므로 보고서용 수치는 발표 PC에서 다시 측정하세요. 카메라 입력은 개발 환경에 장치가 없어 실행해 보지 못했습니다.

## 9. GUI

`main.py` (PySide6):
* 입력 선택: **영상 열기 / 카메라 연결**, 모드: 추적 / 원본 재생 / 결과 재생
* **모델 선택**: `models/`, `experiments/`, 루트의 `.pt` 목록 + 파일 직접 선택, **추적기 선택**(기본 / 개선 / 튜닝 설정), **추적 대상**(사람·고양이·개·새), 얼굴 모자이크
* 시작 / 일시정지 / 중지, 박스·ID·이동 궤적·가림 표시 켜기/끄기
* **성능 비교 탭**: `run_mot.py`가 만든 `results/comparison.json`(HOTA·IDF1·MOTA·IDSW·Frag·FPS·ms, 열별 최고값 강조)과
  `benchmark_speed.py`의 속도 표를 표시합니다.

**검증**: 화면 없이(offscreen) GUI를 실행해 `sample.mp4` 추적 90프레임, 결과 저장(459행), 다시 불러와 재생, 성능 비교 탭 표시까지 확인했습니다.

## 10. 결과·가중치·설정 저장과 불러오기

* **추적 결과**: GUI의 *결과 저장*이 `frame, time_ms, id, class, x1, y1, x2, y2, score, status, direction, distance_px, speed_px_s` CSV와
  같은 이름의 JSON(원본 영상, FPS, 모델·추적기 설정)을 저장합니다. *결과 불러오기*는 모델 없이 저장된 결과를 영상 위에 다시 재생합니다.
* MOT 형식 결과(`results/mot/<실험>/<추적기>/<seq>.txt`)도 저장되어 TrackEval로 다시 평가할 수 있습니다.
* **가중치**: `train_models.py --install`이 `models/*.pt`와 학습 설정·성능 `models/*.json`을 함께 저장합니다.
* **설정**: GUI *설정 저장/불러오기*(모델, 추적기, 대상 클래스, 모자이크, 표시 옵션), 튜닝된 추적기 설정 `configs/*.json`.

## 확장 기능

* **얼굴 자동 모자이크 (개인정보 보호)**: WIDER FACE로 학습한 `models/face.pt`로 찾은 얼굴을 모자이크합니다. GUI에서 켜고 끌 수 있습니다.
* **다중 클래스 추적**: COCO의 고양이·개·새도 사람과 함께 추적합니다. 클래스가 다른 객체끼리는 연결하지 않습니다.
* **결과 재생**: 저장한 추적 결과를 모델 없이 다시 재생해 검토합니다. 재생 화면에는 원본 영상이 나오므로 얼굴 모자이크는 적용되지 않습니다.
