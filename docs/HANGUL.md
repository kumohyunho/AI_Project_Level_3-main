# 확장 기능: 떠다니는 한글 자음·모음 검출·추적

담당: Pdint (Claude) · 브랜치 `claude/hangul` · 코드 `extensions/hangul.py`, `hangul_dataset.py`

화면 위를 떠다니는 한글 **자음·모음 하나하나를 객체로** 보고, 각각에 고유 ID를 붙여 추적하면서 어떤 자모인지 표시합니다.
단어를 읽는 OCR은 쓰지 않습니다. 검출기가 자모 40종을 바로 분류합니다.

## 1. 검출 대상 (40클래스)

| 구분 | 자모 | 개수 |
|---|---|---:|
| 기본 자음 | ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ | 14 |
| 쌍자음 | ㄲ ㄸ ㅃ ㅆ ㅉ | 5 |
| 기본 모음 | ㅏ ㅑ ㅓ ㅕ ㅗ ㅛ ㅜ ㅠ ㅡ ㅣ | 10 |
| 복합 모음 | ㅐ ㅒ ㅔ ㅖ ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ | 11 |

클래스 번호와 이름(로마자 자모 이름, 예: `giyeok` = ㄱ)은 `extensions/hangul.py`의 `JAMO` 표가 기준입니다.
순서를 바꾸면 가중치를 다시 학습해야 합니다.

## 2. 데이터: 직접 만드는 합성 데이터

떠다니는 자모의 추적 정답(ID)이 있는 공개 데이터나 주어진 영상이 없어, 정답을 아는 데이터를 `hangul_dataset.py`로 만듭니다.

* **검출 학습 이미지**: 배경(`sample.mp4` 프레임, 사진 폴더, 무늬) 위에 자모 3~14개. 글꼴·크기·색·외곽선·바탕 판(풍선·카드)·회전을 무작위로.
* **떠다니는 자모 영상** (MOT 형식): 자모 8~14개가 떠다니며 천천히 회전하고, 교차하고, 가림막에 가려지고, 화면 밖으로 나갔다 다시 들어옵니다.
  같은 자모가 여러 개 함께 나옵니다. ID별 자모는 `gt/objects.json`, 프레임별 회전 각도는 `gt/angles.csv`.
* **분할**: train / val / test를 따로 생성. 글꼴이 5개 이상이면 약 20%는 test에서만 씁니다.
* **회전 범위 ±45°** (`--rotation`).

## 3. 자모 추적이 어려운 점과 대응

| 어려운 점 | 대응 |
|---|---|
| **회전하면 다른 글자가 됩니다.** ㅏ를 180° 돌리면 ㅓ, ㅗ↔ㅜ, ㄱ↔ㄴ, ㅡ를 90° 돌리면 ㅣ | 회전을 ±45°로 제한 (이 범위에서는 원래 글자를 구분할 수 있음) |
| **좌우 반전 증강**을 쓰면 ㅏ가 ㅓ로 학습됩니다. | 학습할 때 `--fliplr 0` |
| 회전·가림 때문에 **프레임마다 검출 클래스가 바뀔 수 있습니다.** 기존 추적기는 클래스가 다르면 연결하지 않아 ID가 끊깁니다. | 추적은 클래스와 무관하게 위치·움직임으로 연결하고, 자모는 **트랙별 다수결**로 정합니다 (2단계) |
| **모양이 똑같은 객체**(같은 색 ㄱ 두 개)는 외형으로 구분할 수 없습니다. | 칼만 필터의 움직임 예측으로 구분. 기본판·개선판 비교 대상 |
| ㅡ, ㅣ처럼 **매우 얇은 자모**는 박스가 작아 검출이 어렵습니다. | 박스에 여유를 두고 생성, 클래스별 성능을 따로 확인 |

## 5. 추적과 자모 판정 방법 (`extensions/hangul.py`)

1. **검출**: 40클래스 검출기를 실행하되 NMS는 클래스와 무관하게 합니다 (`agnostic_nms`).
   같은 자모가 ㅏ와 ㅓ 두 클래스로 겹쳐 검출되어 박스가 두 개 생기는 것을 막습니다.
2. **추적**: ByteTrack에는 모든 검출을 같은 클래스로 넘깁니다. 기존 추적기는 클래스가 다르면 연결하지 않으므로,
   이렇게 해야 프레임마다 검출 클래스가 바뀌어도 ID가 끊기지 않습니다. 추적기 설정은 개선판에서 외형 연결만 끈 것이 기본입니다 (7절).
3. **투표**: 트랙마다 이번 프레임에 겹친(IoU ≥ 0.3) **높은 신뢰도 검출**의 클래스에 검출 신뢰도만큼 표를 줍니다.
   가려져서 점수가 낮아진 검출은 분류가 불안정하므로 추적에는 쓰되 투표에는 넣지 않습니다.
4. **표시**: 표를 가장 많이 받은 자모를 그 트랙의 자모로 표시합니다 (`자3 ㄱ`).
   표를 더할 때마다 그 트랙의 예전 표를 0.97배로 줄여 **최근 판정에 무게**를 둡니다 (`vote_decay`).
   자모끼리 스치며 ID가 뒤바뀌었을 때 예전 자모의 표가 오래 남아 틀린 자모가 표시되던 문제를 줄입니다.
   검증 영상에서 1.0(전체 다수결)·0.97·0.9를 비교해 고른 값입니다 (`results/hangul/val_decay*`).
   객체 목록의 클래스 칸에는 자음/모음, 결과 CSV의 `label` 열에는 자모가 저장됩니다.

`JamoVotes`는 트랙별로 투표한 프레임 수와, 그 프레임의 검출이 다수결과 달랐던 횟수도 세어 둡니다 (3단계 평가에서 사용).

## 6. 평가 방법 (`evaluate_hangul.py`)

떠다니는 자모 영상에서 검출을 한 번만 실행하고, 추적기 설정(기본판·개선판 등)만 바꿔 가며 비교합니다.

| 지표 | 뜻 |
|---|---|
| HOTA·IDF1·MOTA·IDSW·Frag | 보행자 평가와 같은 계산(`metrics.py`). 자모 종류와 무관하게 ID 유지만 봅니다. |
| 검출률 | 정답 박스 중 트랙과 IoU 0.5 이상으로 맞은 비율 |
| 프레임 단위 정확도 | 그 프레임의 높은 신뢰도 검출 클래스가 정답 자모와 같은 비율 |
| 다수결 정확도 (같은 프레임) | 위와 같은 프레임에서, 그때까지의 다수결 자모가 정답과 같은 비율. **다수결 효과 = 다수결 − 프레임 단위** |
| 화면 표시 정확도 (전체) | 가림 등으로 높은 신뢰도 검출이 없던 프레임까지 포함해, 화면에 표시된 자모가 정답과 같은 비율 |
| 트랙 단위 정확도 | 트랙의 최종 자모가, 그 트랙이 가장 오래 따라간 정답 객체의 자모와 같은 비율 |

회전 각도(0~15°, 15~30°, 30~45°)별·자음/모음별·자모별 수치와 자주 헷갈리는 자모 쌍(정답 → 판정)도 함께 냅니다.
결과는 `results/hangul/<name>/`에 저장되고, 추적 지표는 GUI **성능 비교** 탭에도 "한글 자모 <name>"으로 나타납니다.

```powershell
python evaluate_hangul.py datasets/hangul/tracking/test --trackers baseline improved --name test
```

정식 가중치로 얻은 수치는 7절에 있습니다.

## 7. 분석 실험 (4단계)

정식 가중치로 아래 세 가지를 실행해 보고서용 수치를 만듭니다. `colab/train_hangul.ipynb`의 7~8절이 그대로 실행합니다.

| 실험 | 명령 | 확인하려는 것 |
|---|---|---|
| 개선 항목별 효과 | `evaluate_hangul.py <test> --name ablation --images 12 --trackers baseline baseline+appearance baseline+recover_lost baseline+reid_buffer baseline+freeze_out_of_frame improved` | 외형 연결·가림 후 재연결·재진입 ID 복원·화면 밖 위치 고정 중 어느 것이 자모 추적에 효과가 있는가 |
| 실패 사례 | 위 명령의 `--images` | ID 변경·끊김의 원인이 교차(같은 자모/다른 자모)·가림·화면 경계 중 무엇인가, 최종 자모가 틀린 트랙은 어떤 자모인가 |
| 회전 범위 | `hangul_dataset.py --tracking-only --rotation {0,45,90} --seed 100` 후 각각 평가, `evaluate_hangul.py --summarize rot0 rot45 rot90` | 회전이 없을 때, 학습 범위(±45°), 학습 범위 밖(±90°)에서 검출률·분류 정확도·ID 유지가 어떻게 달라지는가 |

* 회전 범위별 영상은 seed가 같으면 자모·출발 위치·속도·배경이 같고 회전만 다릅니다.
* "교차(같은 자모)"는 모양이 같은 객체끼리 스친 경우입니다. 외형으로 구분할 수 없어 움직임 예측에만 의존합니다.

  추적 지표(HOTA 등)는 투표와 무관해 그대로입니다.
* 검출률(정답 박스 중 트랙과 맞은 비율)은 약 81%입니다. 화면 경계에 걸치거나 가림막에 가려진 박스도 정답에 포함되어 있습니다.

* 최종 자모가 틀린 트랙은 기본판에서 108개 중 1개(ㅔ → ㅖ)였습니다. 프레임 단위로 자주 헷갈린 쌍은 ㅛ→ㅗ, ㅊ→ㅈ, ㅔ→ㅖ, ㅜ→ㅠ처럼
  획 하나 차이입니다. 자모용 설정에서 검출률이 낮은 자모는 ㅐ(62%), ㅟ(72%), ㅠ(76%), ㅔ(76%), ㄱ(77%)였습니다.
* (표 감쇠 적용 전) 자모용 설정은 화면 표시 정확도가 기본판보다 조금 낮았습니다 (98.4% → 97.6%, 감쇠 적용 후 98.2%). 재진입 ID 복원이 이전 ID를 **다른 자모**에게
  돌려주면 그 ID에 쌓인 투표가 따라가 틀린 자모가 표시되기 때문으로 보았습니다 (다수결 기준 혼동 상위가 ㅃ→ㅔ, ㅠ→ㄲ처럼 모양이 다른 쌍).
  이를 막는 확인 기능을 만들어 실험했습니다 (아래 "ID 복원 시 자모 확인").
* 사례 그림: `results/hangul/ablation/failures/<추적기>/` (정답 흰색, 이전 ID 빨강, 새 ID 초록).

  올바른 ID 복원까지 취소하기 때문으로 보입니다. 판단에 쓰는 프레임을 늘릴수록 끈 것에 가까워졌습니다.

* 가림 뒤 재등장까지 확인하면 뚜렷하게 나빠졌습니다 (검증 HOTA 66.74 → 60.20~64.49).

* 이제 `evaluate_hangul.py`의 보고서에 **보이는 정도별**(온전히 보임 / 일부 가림·경계 / 거의 안 보임) 검출률이 함께 나옵니다.

**회전 범위에 따른 변화 (자모·출발 위치·속도·배경이 같은 영상, `results/hangul/comparison.md`)**

| 회전 범위 | 추적기 | HOTA | IDF1 | IDSW | 검출률 | 프레임 단위 | 다수결(같은 프레임) | 트랙 단위 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 0° (회전 없음) | 기본판 | 57.57 | 60.19 | 78 | 79.0 | 90.0 | 92.3 | 94.0 |
| 0° | 자모용 설정 | 63.16 | 69.35 | 58 | 79.7 | 89.7 | 92.0 | 94.9 |

  자모를 찾고 따라가는 것은 되지만, 많이 돌아간 자모를 다른 자모로 읽기 때문입니다. 다수결은 이 경우에도 +6.7%p를 회복합니다.
* 이 영상 세트의 분류 정확도(약 90%)가 위 test 세트(약 95%)보다 낮은 것은 영상에 나온 자모 구성이 다르기 때문입니다.
  회전 범위끼리의 비교에는 영향이 없습니다.

추적기 설정은 검증 영상에서 골랐지만 후보가 7개뿐인 비교이며, 임계값 격자 탐색은 하지 않았습니다.

## 8. 글자 조합과 시연 영상

떠다니던 자모가 모여 글자 모양을 이루면 **글자와 단어로 읽어 함께 표시**합니다 (`extensions/hangul_compose.py`).
추적 결과(ID, 다수결 자모, 박스)만 쓰는 위치 규칙이며 학습하는 부분은 없습니다.

1. **멈춘 자모만** 씁니다 (속도가 자모 크기의 0.35배/초 미만). 떠다니다 우연히 맞물린 자모는 조합하지 않습니다.
2. **모음을 기준**으로 초성을 붙입니다. 세로 모음(ㅏ ㅐ ㅓ ㅔ ㅣ 등)은 왼쪽, 가로 모음(ㅗ ㅜ ㅡ 등)은 위쪽, 섞인 모음(ㅘ ㅢ 등)은 왼쪽 위의 자음입니다.
3. 초성과 중성을 감싼 영역 **바로 아래**의 자음을 종성으로 붙이고, 유니코드 조합으로 한 글자를 만듭니다 (ㅎ + ㅏ + ㄴ → 한).
4. 같은 줄의 글자를 왼쪽부터 잇고, 글자 사이가 많이 벌어지면 단어를 나눕니다.
5. 같은 자리에서 최근 30프레임 중 가장 많이 읽힌 단어를, 8번 이상 읽혔을 때만 표시합니다.

단어는 노란 박스의 별도 객체로 나옵니다 (화면 `자1001 한글`, 객체 목록 클래스 `단어 · 한글`, 결과 CSV `label`). 번호는 1001부터라 자모 ID와 구분됩니다.

**시연 영상** `hangul_demo.mp4` (31초, `hangul_demo.py`로 생성, 단계별 정답은 `hangul_demo.json`):
떠다님 → "한글"로 모임 → 멈춤 → 흩어짐 → "객체추적"으로 모임 → 멈춤 → 흩어짐.
GUI에서 이 영상을 열고 **확장 → 한글 자모**를 켜면 됩니다.

| 단계 (프레임) | 표시된 단어 (프레임 수) |
|---|---|
| 떠다님 (0~149) | 없음 150/150 |
| 모임 "한글" (150~239) | 없음 90/90 |
| 멈춤 "한글" (240~389) | **한글 144/150**, 없음 6/150 (멈춘 뒤 표시까지 약 0.2초) |
| 흩어짐 (390~539) | 없음 144/150, 한글 6/150 (흩어지기 직전 잔상) |
| 모임 "객체추적" (540~629) | 없음 85/90, 저 5/90 |
| 멈춤 "객체추적" (630~779) | **객체추적 127/150**, 체추적 15/150, 저 4/150, 없음 4/150 |
| 흩어짐 (780~929) | 없음 143/150, 객체추적 7/150 |

* `models/hangul_jamo.pt`로 이 저장소에서 실행한 결과입니다. 떠다니는 동안 잘못 읽힌 단어는 없었습니다.
* "객체추적" 초반의 "체추적"은 "객"의 자모가 모이며 다른 자모와 스쳐 ID가 바뀐 직후, 예전 표가 남아 있던 구간으로 보입니다.
* 시연 글꼴은 나눔스퀘어 굵게(크기 96)입니다. 글꼴 4종·크기 3종을 비교해, 모인 자모가 멈춤 구간 내내 모두 정확히 검출된 조합을 골랐습니다.
  같은 생성기라도 글꼴·크기에 따라 ㅏ가 ㅑ로 읽히는 등 결과가 달라집니다.
* 다른 단어로 만들려면 `python hangul_demo.py --words 인공지능 객체추적 --output my_demo.mp4`. 겹받침(ㄳ, ㄺ 등)이 있는 글자는 만들 수 없습니다.

## 10. 한계

* 합성 데이터로만 학습·평가하므로 실제 촬영 영상(손글씨, 조명 변화 등)에서의 성능은 확인하지 못합니다.
* 회전이 ±45°를 넘는 자모는 다른 자모로 분류될 수 있습니다.
* 가시 비율(visibility)은 화면 경계와 가림막만 반영하고, 자모끼리 겹친 부분은 반영하지 않습니다.
* 자모는 감쇠한 다수결로 정하므로, 처음 몇 프레임이 잘못 분류되거나 ID가 바뀌면 표시가 잠시 틀릴 수 있습니다.
* 글자 조합은 화면 배치만 보는 단순 규칙이라, 자모가 기울어져(약 ±20° 넘게) 멈추거나 배치가 흐트러지면 틀리게 합칠 수 있습니다.
  조합 정확도는 시연 영상 한 편으로만 확인했고, 따로 평가 세트를 만들지는 않았습니다.
